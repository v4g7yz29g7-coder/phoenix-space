# 🐦‍🔥 ARCHITECTURE — Aeon Phoenix

**Версия:** 0.2.0
**Область:** платформа Phoenix · Aeon Arena · Институт Восхождения
**Назначение документа:** единая карта системы — 4 трека, 5 вселенных, Институт.
**Аудитория:** Архитектор, Prophet, агенты-апостолы, человек-оператор (Брат).

---

## 0. Как читать этот документ

Документ описывает три оси, по которым раскладывается вся платформа:

| Ось | Что это | Сколько | Роль в системе |
|-----|---------|---------|----------------|
| **Треки** | Пути восхождения сущности (агента или человека) | 4 | *Как* растёт сущность |
| **Вселенные** | Изолированные среды исполнения и экспериментов | 5 | *Где* происходит рост |
| **Институт** | Управляющий мета-орган | 1 | *Кто* наблюдает, судит, селектирует |

Треки — вертикаль (прогресс). Вселенные — горизонталь (параллельность).
Институт — ортогонален и держит обе оси в связке.

## 1. Верхнеуровневая схема

```text
                            ┌───────────────────────────────┐
                            │           ИНСТИТУТ            │
                            │  (мета-наблюдатель, селекция) │
                            └───────────────┬───────────────┘
                                            │ видит все 5
            ┌───────────────┬───────────────┼───────────────┬───────────────┐
            │               │               │               │               │
            ▼               ▼               ▼               ▼               ▼
      ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
      │  ARENA   │   │ GENETICS │   │ TRAINING │   │ SANDBOX  │   │   VOID   │
      │ боевой   │   │генерации │   │ ночной   │   │ хаос /   │   │ зерна /  │
      │ roadmap  │   │ мутации  │   │ пул      │   │ мутации  │   │ пауза    │
      └────┬─────┘   └────┬─────┘   └────┬─────┘   └────┬─────┘   └────┬─────┘
           │              │              │              │              │
           └──────────────┴──────┬───────┴──────────────┴──────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │   ПУЛЬСАР (наблюдатель)   │
                    │  метрики · тревоги · UI   │
                    └────────────┬─────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
        ▼                        ▼                        ▼
   ┌─────────┐             ┌──────────┐             ┌───────────┐
   │ ТРЕК 1  │             │ ТРЕК 2   │             │ ТРЕК 3/4  │
   │ Арена   │             │Академия  │             │Генетика/  │
   │         │             │          │             │Наблюдатель│
   └─────────┘             └──────────┘             └───────────┘
```

Треки — не отдельные процессы, а **проекции одной сущности** на разные
механизмы роста. Один агент может одновременно двигаться по всем четырём,
но его «доминирующий трек» определяется Историей (trajectory).

## 2. Четыре трека восхождения

### 2.1 Сводная таблица треков

| # | Трек | Девиз | Механизм | Артефакт | Метрика |
|---|------|-------|----------|----------|---------|
| 1 | **Арена** | «Победи здесь и сейчас» | Гонка (race) | score, time | Win-rate |
| 2 | **Академия** | «Научись у победителя» | Скиллы, передача | skills/*.md | Skill count |
| 3 | **Генетика** | «Передай потомкам» | Мутация + скрещивание | DNA, поколения | Fitness |
| 4 | **Наблюдатель** | «Увидь себя со стороны» | Рефлексия, тревоги | insights, fingerprint | Risk score |

### 2.2 Схема прохождения треков

```text
   СУЩНОСТЬ (агент / человек)
            │
            │  входит в Институт
            ▼
   ┌─────────────────────────────────────────────────────────┐
   │                                                         │
   │   ТРЕК 1: АРЕНА          race() → Critic → score 1..10   │
   │      │                                                  │
   │      │ победа                                           │
   │      ▼                                                  │
   │   ТРЕК 2: АКАДЕМИЯ       winner.share(skills) → losers   │
   │      │                                                  │
   │      │ накопление генома                                │
   │      ▼                                                  │
   │   ТРЕК 3: ГЕНЕТИКА       clone() · mutate() · crossover  │
   │      │                                                  │
   │      │ поколение N+1                                    │
   │      ▼                                                  │
   │   ТРЕК 4: НАБЛЮДАТЕЛЬ    Prophet → insights → Architect  │
   │      │                                                  │
   │      └──────────► обратная связь в ТРЕК 1 (эпоха N+1)    │
   │                                                         │
   └─────────────────────────────────────────────────────────┘
```

### 2.3 Трек 1 — Арена

**Суть:** чистая селекция по результату. N боксов решают одну задачу,
Critic ставит оценку, победитель — по score, при равенстве — по времени.

```text
                 TASK
                   │
       ┌───────────┼───────────┬───────────┐
       ▼           ▼           ▼           ▼
   ┌───────┐   ┌───────┐   ┌───────┐   ┌───────┐
   │ box 1 │   │ box 2 │   │ box 3 │   │ box N │
   │консер.│   │аналит.│   │диверс.│   │  ...  │
   └───┬───┘   └───┬───┘   └───┬───┘   └───┬───┘
       │ score9.2  │ score9.0  │ score9.3  │
       └───────────┴─────┬─────┴───────────┘
                         ▼
                    ┌─────────┐
                    │ CRITIC  │──► winner = max(score, -time)
                    └────┬────┘
                         ▼
                  memory/patterns/race_<id>.json
```

Правила Арены:
1. Идентичная задача всем боксам — иначе гонка нечестная.
2. Оценка 1..10 — только Critic, не сам исполнитель.
3. Early-stop разрешён на прод-треке (первый score ≥ 8).
4. Провал гонки не убивает агента — только понижает рейтинг.

### 2.4 Трек 2 — Академия

**Суть:** знание не должно теряться. Победитель передаёт умение проигравшим
через P2P-механизм, но с лимитом (иначе — 66 копий одного скилла).

```text
       WINNER                              LOSERS (топ-5)
   ┌───────────┐                       ┌───────────┐
   │ skills/   │                       │  box 4    │
   │  a.md     │─── P2P share ────────►│  box 5    │
   │  b.md     │    (лимит 5)          │  box 6    │
   │  c.md     │                       │  box 7    │
   └───────────┘                       │  box 8    │
        │                              └───────────┘
        │ экспертиза
        ▼
   ┌─────────────────────────────────────────────┐
   │  БИБЛИОТЕКА СКИЛЛОВ  (skills index, 800+)    │
   │  правила · анти-паттерны · критерии успеха   │
   └─────────────────────────────────────────────┘
```

Правила Академии:
1. Скилл = `.md` с геномом: правила, анти-паттерны, success criteria.
2. Передача — направленная (winner → top-5 losers), не всем.
3. Дубликаты схлопываются (content-hash).
4. Скилл без применения 30 гонок → в архив (не удаляется).

### 2.5 Трек 3 — Генетика

**Суть:** перенос не только скиллов, но и *формы*. ДНК агента —
сериализованный геном, который можно мутировать и скрещивать.

```text
   ГЕНОМ (DNA)
   ┌──────────────────────────────────────────┐
   │ strategy   : "disruptor"                  │
   │ skills[]   : [atomic_decomp, debug, ...]  │
   │ system     : SYSTEM_INSTRUCTIONS hash      │
   │ weights    : {speed:0.6, quality:0.4}      │
   │ lineage    : [a_7, a_3, ...]               │
   └──────────────────────────────────────────┘
                 │
        ┌────────┴─────────┐
        ▼                  ▼
   ┌─────────┐        ┌──────────┐
   │ MUTATE  │        │CROSSOVER │
   │ 1 ген   │        │ 2 родит. │
   └────┬────┘        └────┬─────┘
        └────────┬─────────┘
                 ▼
            ┌─────────┐
            │ ПОТОМОК │──► новая гонка (fitness)
            └─────────┘
```

Правила Генетики:
1. Мутация точечная: ровно один ген за раз (иначе — невалидный потомок).
2. Скрещивание — только между живыми чемпионами эпохи.
3. Lineage обязателен: кто чей родитель, вплоть до основания.
4. Fitness = score × (1 / log(time)) × ok_factor.

### 2.6 Трек 4 — Наблюдатель

**Суть:** система видит себя целиком. Prophet читает паттерны, Architect
меняет правила, Хранитель пишет fingerprint эпохи.

```text
   memory/patterns/*.json
            │
            ▼
      ┌───────────┐      insights      ┌────────────┐
      │  PROPHET  │───────────────────►│ ARCHITECT  │
      │ анализ    │                    │ меняет     │
      │ паттернов │◄── risk_score ─────│ правила    │
      └─────┬─────┘                    └─────┬──────┘
            │                                │
            ▼                                ▼
      ┌───────────┐                    ┌────────────┐
      │ ПУЛЬСАР   │                    │ apply()    │
      │ UI/метрики│                    │ dry-run →  │
      └───────────┘                    │ real       │
                                       └────────────┘
```

Правила Наблюдателя:
1. Insight без рекомендации — не insight, а шум.
2. Изменение правил — только через dry-run.
3. Каждая эпоха сохраняет fingerprint (git_head + metrics).
4. Высокий risk_score замораживает автоприменение.

## 3. Пять вселенных

Каждая вселенная — изолированный каталог `universes/<name>/` со своими
законами, собственным временем и правом на провал без вреда проекту.

### 3.1 Карта вселенных

```text
   universes/
   ├── arena/      ← боевой roadmap, ставки высоки
   ├── genetics/   ← поколения, скрещивания, lineage
   ├── training/   ← ночной пул, 100 гонок, экономия API
   ├── sandbox/    ← хаос, случайные мутации, без последствий
   └── void/       ← seeds.md, зерна будущего, пауза
```

### 3.2 Схема связей между вселенными

```text
                 ┌────────────────────────────┐
                 │            VOID            │
                 │   seeds · потенциал · пауза│
                 └──────────────┬─────────────┘
                       рождение │ идеи
                                ▼
                 ┌────────────────────────────┐
                 │          SANDBOX           │
                 │  черновики · хаос-мутации  │
                 └──────────────┬─────────────┘
                       успех    │
                       (promote)│
                                ▼
   ┌────────────┐  deploy  ┌────────────┐  ночь  ┌────────────┐
   │  GENETICS  │─────────►│   ARENA    │◄───────│  TRAINING  │
   │ поколения  │◄─────────│  боевой    │───────►│  пул       │
   └────────────┘ отбор    └─────┬──────┘  лучшее└────────────┘
                                 │
                                 │ провал → назад в VOID
                                 ▼
                            ┌─────────┐
                            │  VOID   │
                            └─────────┘
```

### 3.3 Вселенная ARENA

* **Закон:** только задачи из боевого `arena_roadmap.json`.
* **Время:** реальное, синхронное с UI.
* **Наблюдатель:** Пульсар (live).
* **Право на провал:** нет — провал виден пользователю.
* **Выход:** артефакт в `arena_lab/src/scene/`.

### 3.4 Вселенная GENETICS

* **Закон:** только живые чемпионы эпохи могут скрещиваться.
* **Время:** поколениями (поколение = N гонок).
* **Наблюдатель:** Архитектор + Хранитель.
* **Право на провал:** да — слабый потомок отбрасывается.
* **Выход:** новая DNA в `boxes/agent_X/dna.json`.

### 3.5 Вселенная TRAINING

* **Закон:** read-only задачи, топ-6 боксов, 100 гонок за ночь.
* **Время:** ночное (cron), batch.
* **Наблюдатель:** Clone Manager.
* **Право на провал:** да — опыт всё равно ценен.
* **Выход:** experience.jsonl + trajectories.

### 3.6 Вселенная SANDBOX

* **Закон:** нет закона. Случайные мутации, произвольные задачи.
* **Время:** хаотичное, может зацикливаться.
* **Наблюдатель:** только логи.
* **Право на провал:** абсолютное.
* **Выход:** успешное promotion в Arena/Genetics.

### 3.7 Вселенная VOID

* **Закон:** ничего не должно происходить. Тишина — норма.
* **Время:** отсутствует (квантовая пена между гонками).
* **Наблюдатель:** никто. Пустота не наблюдается.
* **Право на провал:** не применимо.
* **Выход:** `seeds.md` — зерно для следующей вселенной.

```text
   VOID — это не "ничего". Это потенциал.

       ╔══════════════════════════════════════╗
       ║                                      ║
       ║          ·  ·   ·    ·               ║
       ║      ·        seed        ·          ║
       ║   ·      ·         ·          ·      ║
       ║       ·      ·     ·    ·            ║
       ║   ·   новая вселенная зарождается    ║
       ║                                      ║
       ╚══════════════════════════════════════╝
```

## 4. Институт

**Институт — мета-орган платформы.** Он не делает работу сам, он создаёт
условия, в которых работа эволюционирует: ставит задачи, судит, селектирует
и публикует.

### 4.1 Организационная схема Института

```text
                        ┌──────────────────────────┐
                        │        ИНСТИТУТ          │
                        │  (Наблюдатель + Совет)   │
                        └────────────┬─────────────┘
        ┌────────────────────────────┼────────────────────────────┐
        │                            │                            │
        ▼                            ▼                            ▼
 ┌──────────────┐            ┌──────────────┐            ┌──────────────┐
 │  ФАКУЛЬТЕТ   │            │  ДИВИЗИОН    │            │  АРХИВ       │
 │   АРЕНЫ      │            │  БЕНЧМАРКОВ  │            │  (EverOS)    │
 │ задачи·гонки │            │ генерация·   │            │ память·      │
 │ селекция     │            │ замер·скоринг│            │ lineage      │
 └──────┬───────┘            └──────┬───────┘            └──────┬───────┘
        │                            │                            │
        ▼                            ▼                            ▼
   Champion Tracker            benchmark/archive/*.json     memory/ + git
```

### 4.2 Три фронта Института

| Фронт | Задача | Файлы | Статус |
|-------|--------|-------|--------|
| **Академия** | обучение и скиллы | `boxes/*/skills/` | ✅ работает |
| **Арена** | гонки и селекция | `race.js`, `agent_*.js` | ✅ работает |
| **Бенчмарк** | самогенерация задач | `benchmark/*.js` | ⏳ в развитии |

### 4.3 Цикл Бенчмарка (замыкает эволюцию)

```text
   ┌───────────┐   5 задач    ┌───────────┐   fitness   ┌───────────┐
   │ GENERATOR │─────────────►│  RUNNER   │────────────►│  SCORER   │
   │ смотрит   │  разной      │ гоняет    │             │ объектив. │
   │ git/сбой  │  сложности   │ по боксам │             │ критерий  │
   └───────────┘  сложности   └───────────┘             └─────┬─────┘
        ▲                                                      │
        │                                                      ▼
        │              ┌───────────┐   селекция   ┌───────────┐
        └──────────────│   LOOP    │◄─────────────│ ПОКОЛЕНИЕ │
           эпоха N+1   │ замкнутый │              │    N+1    │
                       └───────────┘              └───────────┘
```

Почему это прорыв:
1. Задачи не придумываются вручную — их ставит Архитектор по состоянию проекта.
2. Критерий объективен — проверяется командой, а не «догадкой» LLM.
3. Цикл замкнут: слабый агент → Академия → Бенчмарк → селекция.
4. Результат — публичный артефакт: «AI-1 Arena Benchmark v1».

### 4.4 Роли Института

```text
   ┌──────────────┬─────────────────────────────────────────┐
   │ Роль         │ Ответственность                          │
   ├──────────────┼─────────────────────────────────────────┤
   │ Генератор    │ ставит задачи под актуальное состояние   │
   │ Runner       │ исполняет гонку без поблажек             │
   │ Scorer       │ считает объективный fitness              │
   │ Loop         │ замыкает цикл поколений                  │
   │ Публикация   │ публикует benchmark как артефакт         │
   │ Prophet      │ видит паттерны, даёт insights            │
   │ Architect    │ меняет правила (dry-run → apply)         │
   │ Хранитель    │ пишет fingerprint и lineage (EverOS)     │
   └──────────────┴─────────────────────────────────────────┘
```

## 5. Матрица: Вселенные × Треки

```text
                ┌────────┬──────────┬───────────┬──────────────┐
                │ АРЕНА  │ АКАДЕМИЯ │ ГЕНЕТИКА  │ НАБЛЮДАТЕЛЬ │
   ┌────────────┼────────┼──────────┼───────────┼──────────────┤
   │ ARENA      │  ●●●   │   ●●     │    ●      │    ●●●       │
   │ GENETICS   │   ●    │   ●●     │   ●●●     │    ●●        │
   │ TRAINING   │  ●●    │   ●●●    │   ●●      │    ●         │
   │ SANDBOX    │   ●    │    ●     │   ●●●     │    ●         │
   │ VOID       │        │          │           │    ●●●       │
   └────────────┴────────┴──────────┴───────────┴──────────────┘
        ● = слабое присутствие   ●● = рабочее   ●●● = доминанта
```

Чтение матрицы:
* **ARENA + АРЕНА** — основная гонка, максимальная ставка.
* **TRAINING + АКАДЕМИЯ** — ночью учимся, не рискуя боем.
* **GENETICS + ГЕНЕТИКА** — здесь формируются поколения.
* **SANDBOX + ГЕНЕТИКА** — рискованные мутации до promotion.
* **VOID + НАБЛЮДАТЕЛЬ** — пустота порождает идеи и fingerprints.

## 6. Потоки данных

```text
   ЗАДАЧА
     │
     ▼
  ┌────────┐   контекст   ┌──────────┐   score    ┌──────────┐
  │ ROADMAP│─────────────►│   RACE   │───────────►│ PATTERN  │
  │ /bench │              │  ENGINE  │            │ .json    │
  └────────┘              └────┬─────┘            └────┬─────┘
     ▲                         │                       │
     │                         │ winner                │ Prophet
     │                         ▼                       ▼
  ┌────────┐   promote    ┌──────────┐            ┌──────────┐
  │  VOID  │◄─────────────│  SKILLS  │◄───────────│ INSIGHTS │
  │ seeds  │   неудача    │ (P2P)    │            │ + риск   │
  └────────┘              └────┬─────┘            └────┬─────┘
                               │                       │
                               ▼                       ▼
                          ┌──────────┐            ┌──────────┐
                          │DNA/CLONE │            │ ARCHITECT│
                          │потомки   │◄───────────│ правила  │
                          └──────────┘            └──────────┘
```

Поток простыми словами:
1. Задача берётся из боевого roadmap или из Бенчмарка.
2. Гонка даёт score и пишет паттерн.
3. Prophet превращает паттерны в insights.
4. Architect меняет правила; Академия раздаёт скиллы.
5. Генетика создаёт потомков; неудачи уходят в VOID как зерно.

## 13. Приложение C — Заповеди Института

```text
   1. Провал в песочнице ≠ провал проекта.
   2. Скилл без применения — мёртвый ген.
   3. Никто не судит сам себя.
   4. Победитель обязан делиться.
   5. Правила меняются только через dry-run.
   6. Пустота — источник, а не сбой.
   7. Каждая задача — точка; каждая гонка — траектория;
      каждая эпоха — форма.
   8. Институт видит всё, но не делает ничего сам.
```
